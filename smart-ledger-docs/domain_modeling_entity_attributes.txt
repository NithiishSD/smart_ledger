4.3 Define Entity Attributes

Based on everything we locked in Steps 1–3 and the classification from 4.2, we can define the initial attributes.

1. Customer

Represents a person/business who buys silk or warp.

Attribute	Purpose
Customer ID	Unique identity
Name	Customer identification
Phone	Contact
WhatsApp Number	Communication
Address	Delivery/contact information
Customer-specific credit terms	Determine expected payment period
Status	Active/inactive
Created Date	Record tracking

Important: We should not store outstanding_amount as a primary attribute. It should be derived from orders and payments.

2. Supplier

Represents a silk/raw-material supplier.

Attribute	Purpose
Supplier ID	Unique identity
Name	Supplier identification
Phone	Contact
WhatsApp Number	Communication
Address	Supplier information
Default Credit Period	Default supplier terms
Status	Active/inactive
Created Date	Record tracking

The actual credit period of a particular purchase can differ from the supplier's default.

3. Purchase

Represents a raw silk purchase from a supplier.

Attribute	Purpose
Purchase ID	Unique identity
Supplier	Who supplied it
Purchase Date	When purchased
Weight	Quantity of silk
Rate/kg	Purchase price
Total Amount	Purchase value
Payment Type	Cash/credit/etc.
Credit Period	If purchased on credit
Due Date	Supplier payment expectation
Bill Number	Supplier bill reference
Status	Pending/received/returned/etc.
Notes	Additional information
Important distinction

The Purchase represents the business obligation/acquisition.

The actual payment is represented separately by Payment / Financial Transaction.

So:

Purchase ≠ Payment

4. Raw Material Lot

This is currently a tentative entity from 4.2.

If we retain it, it represents a distinguishable quantity of raw silk received through a purchase.

Attribute	Purpose
Lot ID	Identify material
Purchase Reference	Where it came from
Initial Weight	Weight received
Available Weight	Current usable quantity
Allocated Weight	Quantity committed
Status	Available/allocated/consumed/returned
Quality/Condition	If needed
Received Date	Material tracking

This entity is useful if we want to answer:

"Where did this particular silk come from and where did it go?"

We'll finalize whether this is necessary during 4.10.

5. Customer Order

Represents an order placed by a customer.

Attribute	Purpose
Order ID	Unique identity
Customer	Who ordered
Order Date	When ordered
Product Type	Raw silk/Kora/Silk/Vuda
Weight	Ordered quantity
Warp Specification	Required specifications where applicable
Rate/kg	Selling rate
Total Amount	Order value
Advance Amount	Amount already received
Status	Pending/processing/completed/cancelled
Expected Delivery Date	Planning
Actual Delivery Date	Tracking
Notes	Additional requirements

Again:

Outstanding amount should be derived, rather than manually maintained.

6. Production Batch

Represents an in-house production operation.

Attribute	Purpose
Production ID	Unique identity
Product Type	Kora warp etc.
Input Weight	Raw material consumed
Finished Weight	Finished output
Wastage Weight	Recorded wastage
Production Date	When produced
Order Reference	Associated customer demand
Worker/Workers	Who performed work
Production Stage	Rolling/warping/etc.
Status	Planned/In progress/Completed
Notes	Additional information

This lets us track:

Raw silk → Production → Finished warp

7. Worker

Represents an internal worker.

Attribute	Purpose
Worker ID	Identity
Name	Worker name
Phone	Contact
Worker Type	Rolling/Warping
Payment Basis	Hourly/kg
Current Rate	Current applicable rate
Status	Active/inactive
Joining Date	Record

We should not overwrite historical rates when the rate changes.

Historical work records must retain the rate applicable at that time.

8. Work Record

Represents work performed by a worker.

Attribute	Purpose
Work Record ID	Identity
Worker	Who worked
Work Date	Date
Work Type	Rolling/Warping
Hours Worked	For hourly work
Weight Processed	For kg-based work
Applicable Rate	Rate at that time
Calculated Earnings	Work value
Production Reference	Related production
Payment Status	Paid/unpaid

This is separate from worker payment.

Work Record = work performed
Payment = money actually paid

9. Outsourcing Job

Represents raw silk sent to an external manufacturer.

Attribute	Purpose
Job ID	Unique identity
Manufacturer	External party
Date Sent	When material was sent
Raw Silk Weight	Quantity supplied
Warp Type	Kora/Silk
Related Order	Customer demand
Expected Output	Expected finished warp
Received Weight	Actual received
Wastage/Difference	Difference
Rate/kg	Manufacturing rate
Total Payable	Manufacturing cost
Status	Sent/In progress/received/closed
Payment Status	Paid/pending
Notes	Additional information

This becomes the basis for tracking:

Our silk → external manufacturer → finished warp

10. Manufacturer / Job Worker

Represents an external production partner.

Attribute	Purpose
Manufacturer ID	Identity
Name	Manufacturer
Phone	Contact
Address	Contact information
Rate Information	Applicable manufacturing rates
Status	Active/inactive
Notes	Additional information
11. Payment

Represents a payment between parties.

Attribute	Purpose
Payment ID	Identity
Date	Payment date
Payer	Who paid
Receiver	Who received
Amount	Money involved
Payment Method	Cash/UPI/bank/cheque
Purpose	Customer/supplier/worker/etc.
Reference	Related order/purchase/loan/etc.
Status	Pending/completed/reversed
Notes	Additional information

But remember:

A payment is not necessarily the same as the underlying financial transaction.

12. Financial Transaction

This is the money movement record.

Attribute	Purpose
Transaction ID	Identity
Date/Time	When money moved
Transaction Type	Revenue/expense/payment/transfer/etc.
Amount	Money involved
Account	Cash/bank account
Direction	Inflow/outflow
Business Reason	Why it happened
Reference	Related business entity
Status	Pending/cleared/reversed
Description	Explanation

This is particularly important because:

Business event ≠ money movement

For example:

Credit purchase

Purchase occurs → Supplier payable increases
Financial transaction → No cash movement

13. Financial Account

Represents a source/location of actual money.

Attribute	Purpose
Account ID	Identity
Account Name	Example: SBI Current Account
Account Type	Cash/Bank
Opening Balance	Starting position
Bank Details	If applicable
Status	Active/inactive

Physical cash should be represented separately from bank accounts, even though both contribute to available money.

14. Expense

Represents a business expense.

Attribute	Purpose
Expense ID	Identity
Category	Electricity, transport, maintenance, etc.
Amount	Expense amount
Date	Actual payment date
Payment Method	Cash/UPI/bank/cheque
Financial Account	Where money came from
Description	Reason
Document Reference	Optional bill/receipt
Status	Recorded/reversed
15. Refund

Represents money/material returned as part of a correction or customer/supplier settlement.

Attribute	Purpose
Refund ID	Identity
Date	Refund date
Amount/Weight	Returned value/material
Reason	Why returned
Related Order/Purchase	Original transaction
Refund Type	Money/material
Settlement Method	Cash/adjustment/etc.
Status	Pending/completed
Notes	Explanation
16. Loan

Represents money borrowed by the business.

Attribute	Purpose
Loan ID	Identity
Lender	Bank/private lender
Loan Type	Bank/private
Original Principal	Initial borrowing
Current Principal	Remaining principal
Interest Information	Interest details
Start Date	Loan start
Due Date	Applicable due date
Status	Active/completed
Notes	Additional information

Actual interest/principal payments belong to financial transactions.

17. Chit

Represents an active chit/investment.

Attribute	Purpose
Chit ID	Identity
Name/Identifier	Identify chit
Start Date	Beginning
Duration	Number of periods
Contribution Amount	Current contribution
Status	Active/completed
Payout Date	If received
Payout Amount	Lump sum received
Bidding Information	Auction/bid information
Remaining Contribution	Expected remaining obligation
Notes	Additional information

The exact bidding calculation remains:

CHIT_BIDDING_CALCULATION

until the actual business formula is finalized.

18. Bill / Invoice

Represents a business document.

Attribute	Purpose
Bill ID	Identity
Bill Number	Unique document number
Bill Date	Date
Bill Type	Sales/Purchase/etc.
Related Transaction	Source transaction
Customer/Supplier	Related party
Amount	Document value
Document Location	Stored document
Status	Generated/cancelled/corrected
Version/Correction Reference	Preserve history

Important:

Bill existence does not mean payment has occurred.

19. Notification

Represents an alert/reminder generated by the system.

Attribute	Purpose
Notification ID	Identity
Type	Supplier/customer/loan/stock/etc.
Related Entity	What it concerns
Priority	High/medium/low
Trigger Date	When generated
Scheduled Time	When to send
Status	Pending/sent/read/resolved
Message	Notification content
20. Notification Configuration

Supporting configuration rather than a major business entity.

Attribute	Purpose
Notification Type	What kind
Enabled	On/off
Reminder Timing	Days before/after
Frequency	How often
Priority	Importance
What we should NOT make attributes

This is just as important as deciding what to include.

We should not directly store things such as:

customerOutstanding
supplierOutstanding
cashBalance
bankBalance
totalProfit
availableInventory

as manually editable business values.

Instead, these should be derived from the underlying transactions and records.

For example:

Customer Outstanding

Sales/Orders − Payments − Adjustments

Supplier Payable

Credit Purchases − Supplier Payments − Adjustments

Available Money

Physical Cash + Cleared Bank Balances

This prevents the classic problem:

Database says ₹2,00,000 but actual transactions add up to ₹1,80,000.

4.3 Output

At the end of 4.3, we should have a domain attribute catalogue for all important entities.
