# 05 - API Specification (REST, `/api/v1`)

The complete HTTP contract of SmartSilk (Nexora): every endpoint of the first release (**MVP**) and every endpoint that is
specified for later (**POST-MVP**, not built in the first release). Requirement IDs refer to `02-REQUIREMENTS.md`; tables and
columns refer to `04-DATA-MODEL.md`; permissions refer to the `Permission` enum and the matrix in `09-SECURITY.md` section 3.2.

Precedence when documents disagree: `DOMAIN_RULES.md` and `DECISIONS.md`, then `CONVENTIONS.md`, then the reconciled plan
decisions, then this file. Section 22 lists every choice made while writing this file.

Endpoint ids (`E-<MODULE>-<nn>`) are stable and are used by the task list and the tests.

## 1. Global conventions

### 1.1 Base path, transport, content types

| Item | Rule |
|---|---|
| Base path | `/api/v1` (all paths below are relative to it unless they start with `/actuator`) |
| Transport | HTTPS in production (TLS terminated by Caddy); plain HTTP only on a developer machine |
| Request body | `application/json; charset=UTF-8` (multipart only for `POST /documents`). Maximum body 1 MiB (10 MiB file + form fields for documents) |
| Response body | `application/json` for success, `application/problem+json` for every error, `text/csv; charset=UTF-8` when `format=csv` is requested, the stored content type for document downloads |
| Field names | JSON `camelCase`. Unknown request fields are ignored (they can never set derived values, ids, numbers, statuses or timestamps) |
| Null fields | Optional response fields are present with `null` when unknown (stable shape for the client) |
| Ids | UUID strings (`"3f2b8c1e-5d6a-4e1b-9c2d-7a8b9c0d1e2f"`). A malformed path id is 400 `MALFORMED_REQUEST` |
| Business numbers | `PREFIX-YYYY-NNNN` strings generated by the backend (`PTY`, `PUR`, `RCT`, `RTN`, `MOV`, `ORD`, `PAY`, `BAT`, `JOB`, `EXP`, `TRF`, `LON`, `CHT`) |
| Methods | `GET` read, `POST` create or business action (sub-resource such as `/purchases/{id}/receipts`), `PATCH` partial update of editable master/aggregate fields, `PUT` only for configuration (`/notifications/configurations/{type}`). There is **no `DELETE` endpoint** and no `PUT` on amounts: such calls return 405 `METHOD_NOT_ALLOWED` |
| Status codes | `201` + `Location` for creates; `200` with a body for reads and for actions that return the changed resource; `204` for actions without a body |

### 1.2 Authentication header

Every endpoint except the public ones (FR-AUTH-12) needs `Authorization: Bearer <access token>`.

| Public endpoint | Notes |
|---|---|
| `POST /auth/login`, `POST /auth/refresh`, `POST /auth/logout` | rate limited per IP (section 1.8) |
| `GET /actuator/health`, `GET /actuator/health/**`, `GET /actuator/info` | details hidden in production |
| `GET /v3/api-docs/**`, `GET /swagger-ui.html`, `GET /swagger-ui/**` | dev profile only; 404 in production |

An unauthenticated request to any other URL, including unknown URLs, is 401 (the caller learns nothing about which URLs exist).

### 1.3 Numbers, dates and units

| Kind | JSON | Rule |
|---|---|---|
| Money (rupees) | **JSON number** with exactly 2 decimals in responses (`45000.00`) | Serialized from `BigDecimal` (scale 2, HALF_UP). Requests accept a number with at most 2 decimals; more decimals are 400 `VALIDATION_FAILED` (never silently rounded). Clients must parse money with a decimal type (Kotlin `BigDecimal`), never `Double`/`Float` |
| Weight (kg) | JSON number with exactly 3 decimals (`42.500`) | `BigDecimal` scale 3. Requests: at most 3 decimals, else 400 `VALIDATION_FAILED` (FR-INV-15) |
| Hours | JSON number with 2 decimals (`8.00`) | `BigDecimal` scale 2 |
| Percent | JSON number (`4.00`) | 2 decimals in responses |
| Business date | string `yyyy-MM-dd` | Asia/Kolkata calendar. Must lie between today minus 10 years and today plus 366 days (custom constraint `@BusinessDate`), else 400 `VALIDATION_FAILED` |
| Timestamp | string ISO-8601 UTC (`2026-10-07T10:15:30Z`) | `Instant` |
| Enum | string, exact upper-case value | Unknown value in a body or query parameter is 400 `MALFORMED_REQUEST` (FR-PARTY-02 AC2) |
| Boolean | `true` / `false` | |

### 1.4 Reusable validation types

Every request field table below uses these names. All are Jakarta Validation constraints on Java `record` DTOs.

| Name | JSON type | Constraints |
|---|---|---|
| `Money+` | number | `@NotNull @DecimalMin("0.01") @Digits(integer = 12, fraction = 2)` (max 999999999999.99) |
| `Money0` | number | `@NotNull @DecimalMin("0.00") @Digits(integer = 12, fraction = 2)` |
| `Kg+` | number | `@NotNull @DecimalMin("0.001") @Digits(integer = 9, fraction = 3)` |
| `Kg0` | number | `@NotNull @DecimalMin("0.000") @Digits(integer = 9, fraction = 3)` |
| `Hours+` | number | `@DecimalMin("0.01") @Digits(integer = 6, fraction = 2)` |
| `BizDate` | string | `@NotNull` + `@BusinessDate` (section 1.3) |
| `Name200` | string | `@NotBlank @Size(max = 200)` |
| `Notes` | string | optional, `@Size(max = 1000)` |
| `Reason` | string | `@NotBlank @Size(max = 255)` |
| `Ref100` | string | optional, `@Size(max = 100)` (bill number, cheque number, UTR) |
| `Id` | string (UUID) | `@NotNull`, parsed as `UUID` (malformed is 400 `MALFORMED_REQUEST`) |
| `Phone` | string | `@NotBlank @Pattern(regexp = "^[0-9+()\\- ]{6,30}$")` |

A "Validation" cell that says, for example, `Money+` means exactly those constraints; extra rules are written next to it.
Cross-field rules (for example `accepted + rejected <= received`) are checked in the DTO or the service and also return
400 `VALIDATION_FAILED` with an `errors[]` entry naming the field.

### 1.5 Error body (RFC 9457 ProblemDetail)

```json
{
  "type": "about:blank",
  "title": "Conflict",
  "status": 409,
  "detail": "Only 42.500 kg of RAW_SILK available in RAW_STOCK.",
  "instance": "/api/v1/production-batches/1b6a.../start",
  "code": "INSUFFICIENT_INVENTORY",
  "timestamp": "2026-10-07T10:15:30Z"
}
```

Validation failures add `errors`:

```json
{
  "type": "about:blank", "title": "Bad Request", "status": 400,
  "detail": "Request validation failed.", "instance": "/api/v1/parties",
  "code": "VALIDATION_FAILED", "timestamp": "2026-10-07T10:15:30Z",
  "errors": [ { "field": "roles", "message": "must not be empty" } ]
}
```

`detail` is plain English, at most 200 characters, never a stack trace, SQL or class name (NFR-USE-04). Clients switch on `code`.

### 1.6 Errors common to every endpoint

These apply to every endpoint and are **not repeated** in the per-endpoint error tables (which list only endpoint-specific cases).

| HTTP | `code` | When |
|---|---|---|
| 400 | `MALFORMED_REQUEST` | unparseable JSON, wrong JSON type, unknown enum value, malformed UUID in the path or a query parameter |
| 400 | `VALIDATION_FAILED` | a constraint in the request table fails; unknown `sort` property; `from` later than `to` on any list/report with a date range; missing `Idempotency-Key` where it is required |
| 401 | `UNAUTHENTICATED` | no token, malformed token, wrong signature or issuer (not on public endpoints) |
| 401 | `TOKEN_EXPIRED` | access token past `exp` (not on public endpoints) |
| 403 | `ACCESS_DENIED` | the token lacks the permission named for the endpoint |
| 404 | `RESOURCE_NOT_FOUND` | unknown id in the path, or unknown URL after authentication |
| 405 | `METHOD_NOT_ALLOWED` | `PUT`/`PATCH`/`DELETE` on a resource that does not support it (FR-PARTY-15, FR-PROC-14, FR-PROC-18, FR-INV-01, FR-ORD-17, FR-PAY-16, FR-FIN-04, FR-FIN-14, FR-FIN-17, FR-WORK-03, FR-WORK-07, FR-LOAN-09, FR-OUT-11, FR-PROD-10, FR-DOC-04, FR-PAY-23, NFR-DATA-03) |
| 409 | `CONCURRENT_MODIFICATION` | optimistic-lock (`@Version`) conflict, or a row lock was not obtained within 5 s (FR-INV-06, FR-FIN-10) |
| 413 | `MALFORMED_REQUEST` | body larger than the limit in section 1.1 |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | request `Content-Type` other than JSON (or multipart for documents) |
| 429 | `RATE_LIMITED` | rate limit exceeded; header `Retry-After` (seconds) is set (section 1.8) |
| 500 | `INTERNAL_ERROR` | unexpected failure; logged with the request id, generic `detail` |

### 1.7 Pagination, sorting and filtering

List endpoints take `page` (0-based, default 0), `size` (default 20, maximum 100; larger values are capped to 100, FR-PARTY-07 AC2)
and `sort=<property>,<asc|desc>` (only the properties listed per endpoint; anything else is 400 `VALIDATION_FAILED`). Default sort
is newest first unless stated. Date-range filters `from` / `to` are inclusive business dates. The response is `PageResponse<T>`:

| Field | Type | Notes |
|---|---|---|
| `content` | array of `T` | the rows of this page |
| `page` | integer | 0-based page number |
| `size` | integer | effective page size (after the cap) |
| `totalElements` | integer | total rows across all pages |
| `totalPages` | integer | |

Search text (`search`) is case-insensitive substring matching; `%`, `_` and `\` typed by the user are matched literally (NFR-SEC-10).

**CSV export (FR-RPT-16).** The endpoints marked "CSV" accept `format=csv` with the same filters. The response is
`text/csv; charset=UTF-8` with `Content-Disposition: attachment; filename="<list>-<from>-<to>.csv"`, a header row, money with 2 decimals,
weights with 3, all matching rows (pagination ignored) up to **50000** rows; more is 400 `VALIDATION_FAILED` ("narrow the period").

### 1.8 Rate limits

| Scope | Limit | Response |
|---|---|---|
| Per IP on `/auth/**` | 10 requests per minute | 429 `RATE_LIMITED` + `Retry-After` |
| Per user (JWT `sub`) on everything else | 300 requests per minute (MVP, NFR-SEC-11) | 429 `RATE_LIMITED` + `Retry-After` |
| Login lock per account | 5 consecutive failures, locked 15 minutes | 401 `INVALID_CREDENTIALS` (same as a wrong password) |

### 1.9 Idempotency (retry-sensitive writes)

| Item | Rule |
|---|---|
| Header | `Idempotency-Key: <8-64 characters [A-Za-z0-9-]>`; clients send a fresh UUID per user action and reuse it on retry (NFR-USE-05) |
| Where | **Required** on the endpoints marked "Idempotency: required" (every write that moves money or stock in a way a retry could duplicate). A missing or malformed key there is 400 `VALIDATION_FAILED` (`errors[].field = "Idempotency-Key"`). Ignored everywhere else |
| Scope | per user: the same key from two users never collides |
| Replay | Same key + same request body (SHA-256 of the raw body) within 48 hours: the stored status and body of the first successful response are returned unchanged, with header `Idempotency-Replayed: true`; no second record is created |
| Mismatch | Same key + different body: 409 `DUPLICATE_REQUEST` |
| Concurrency | Two simultaneous requests with the same key: the second waits for the first and then replays (exactly one record, FR-PAY-07 AC3) |
| Failures | A request that fails (4xx business error or 5xx) stores nothing, so a retry after fixing the input runs normally |
| Expiry | Keys are kept 48 hours (`expires_at`); after that the key is treated as new (FR-PAY-07 AC4) |

### 1.10 Common response headers

`X-Request-Id` (echoed if the client sent a valid one, else generated, NFR-OBS-02), `Cache-Control: no-store`,
`X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer` (NFR-SEC-04),
`Strict-Transport-Security` in production (NFR-SEC-01). No CORS headers are sent (NFR-SEC-05).

## 2. Error-code catalogue

The `code` is a stable contract; the `detail` text may be reworded. Source: DOMAIN_RULES section 7 plus the four codes added by the
plan decisions.

| Code | HTTP | Meaning |
|---|---|---|
| `VALIDATION_FAILED` | 400 | Bean Validation or a cross-field rule failed; `errors[]` lists the fields |
| `MALFORMED_REQUEST` | 400 | Unparseable JSON, wrong types, unknown enum value, malformed id; also 413 bodies |
| `UNAUTHENTICATED` | 401 | No valid token (missing, malformed, wrong signature/issuer), unknown or revoked refresh token |
| `TOKEN_EXPIRED` | 401 | Access or refresh token past its expiry |
| `INVALID_CREDENTIALS` | 401 | Wrong username or password, inactive user, or locked account (one identical message) |
| `ACCESS_DENIED` | 403 | Authenticated, but the permission is missing |
| `RESOURCE_NOT_FOUND` | 404 | Unknown id or business number, or unknown URL after authentication |
| `METHOD_NOT_ALLOWED` | 405 | HTTP method not supported (no delete, no edit of history) |
| `UNSUPPORTED_MEDIA_TYPE` | 415 | Wrong request content type, or an uploaded file whose content is not an allowed type |
| `DUPLICATE_BUSINESS_NUMBER` | 409 | A business number unique constraint was hit |
| `DUPLICATE_RESOURCE` | 409 | Another unique value already exists (account name, opening stock for a product/location) |
| `DUPLICATE_REQUEST` | 409 | Idempotency key reused with a different body |
| `CONCURRENT_MODIFICATION` | 409 | Optimistic-lock conflict or a 5 s lock wait timed out; reload and retry |
| `INVALID_STATE_TRANSITION` | 409 | The status change is not legal from the current state (also: closed account, cancel with allocations) |
| `ORDER_LOCKED` | 409 | Edit or cancel of an order after production/outsourcing started, or after payments were allocated |
| `INSUFFICIENT_INVENTORY` | 409 | Stock would go negative (or more than the returnable weight) |
| `INSUFFICIENT_FUNDS` | 409 | Cash or bank balance would go negative |
| `PURCHASE_RECEIPT_EXCEEDED` | 409 | Receiving more than was ordered |
| `OUTSOURCE_RECEIPT_EXCEEDED` | 409 | Receiving (plus wastage) more than was issued |
| `PAYMENT_ALLOCATION_EXCEEDED` | 409 | Allocation above the outstanding, above the payment, or a payment above the total payable; loan repayment above outstanding principal |
| `INVALID_PAYMENT_ALLOCATION` | 422 | Allocation target of another party or of the wrong kind |
| `PRODUCTION_NOT_RECONCILED` | 422 | `input != output + wastage + discrepancy` |
| `INVALID_PARTY_ROLE` | 422 | The party lacks the role the operation needs |
| `PARTY_INACTIVE` | 422 | The party is inactive |
| `INVALID_PRODUCT_FOR_OPERATION` | 422 | Product not allowed for the operation (vuda warp into production, silk warp purchase, product/location mismatch) |
| `INVALID_PAYMENT_METHOD` | 422 | Method inconsistent with the account type, or a non-cash chit transaction |
| `RATE_LIMITED` | 429 | Too many requests; see `Retry-After` |
| `INTERNAL_ERROR` | 500 | Unexpected; never leaks internals |

## 4. Authentication (`/auth`) - module identity

Clients: the desktop application (PLAN_DECISIONS section 10) keeps the access token in memory and the refresh token in the OS
credential store; on 401 it refreshes once and retries. The server's build version is published at `GET /actuator/info`
(`build.version`), so the client can refuse an incompatible API major version.

### E-AUTH-01 `POST /auth/login` - Log in · MVP

| Permission | Idempotency | Success | Requirements |
|---|---|---|---|
| public (rate limited per IP) | none | 200 `TokenResponse` | FR-AUTH-01, FR-AUTH-02, FR-AUTH-07, FR-AUTH-08, NFR-SEC-06 |

**Request**

| Field | Type | Required | Validation | Notes |
|---|---|---|---|---|
| `username` | string | yes | `@NotBlank @Size(max = 100)` | case-insensitive (trimmed and lower-cased before lookup) |
| `password` | string | yes | `@NotBlank @Size(max = 200)` | never logged |

**Response `TokenResponse`**

| Field | Type | Notes |
|---|---|---|
| `accessToken` | string | JWT HS256, claims `iss=nexora`, `sub`, `username`, `roles`, `permissions`, `iat`, `exp` |
| `refreshToken` | string | opaque, 43 characters (32 random bytes, Base64URL); only its SHA-256 hash is stored |
| `tokenType` | string | always `Bearer` |
| `expiresIn` | integer | access-token lifetime in seconds (`900`) |

**Errors**

| HTTP | Code | When |
|---|---|---|
| 401 | `INVALID_CREDENTIALS` | unknown username, wrong password, inactive user, or account locked after 5 consecutive failures (identical `detail` in every case) |
| 429 | `RATE_LIMITED` | more than 10 auth requests per minute from one IP |

**Example**
```json
POST /api/v1/auth/login
{ "username": "owner", "password": "Correct-Horse-9" }
-> 200
{ "accessToken": "eyJhbGciOiJIUzI1NiJ9...", "refreshToken": "q9Yx3b1V...", "tokenType": "Bearer", "expiresIn": 900 }
```

### E-AUTH-02 `POST /auth/refresh` - Rotate tokens · MVP

| Permission | Idempotency | Success | Requirements |
|---|---|---|---|
| public | none | 200 `TokenResponse` | FR-AUTH-04, FR-AUTH-05 |

**Request**

| Field | Type | Required | Validation | Notes |
|---|---|---|---|---|
| `refreshToken` | string | yes | `@NotBlank @Size(max = 200)` | revoked in the same transaction; a new pair is issued |

**Errors**

| HTTP | Code | When |
|---|---|---|
| 401 | `TOKEN_EXPIRED` | the refresh token is past its 7-day expiry |
| 401 | `UNAUTHENTICATED` | unknown token; revoked token (reuse: every refresh token of that user is revoked as well); user deactivated |
| 429 | `RATE_LIMITED` | per-IP auth limit |

**Example**
```json
POST /api/v1/auth/refresh
{ "refreshToken": "q9Yx3b1V..." }
-> 200 { "accessToken": "eyJ...", "refreshToken": "Zr2P0kLm...", "tokenType": "Bearer", "expiresIn": 900 }
```

### E-AUTH-03 `POST /auth/logout` - Revoke a refresh token · MVP

| Permission | Idempotency | Success | Requirements |
|---|---|---|---|
| public | none (idempotent by nature) | 204, no body | FR-AUTH-06 |

**Request**: `refreshToken` (string, required, `@NotBlank @Size(max = 200)`).
**Errors**: common set only; an unknown or already revoked token still returns 204.
**Example**: `POST /api/v1/auth/logout {"refreshToken":"Zr2P0kLm..."}` -> `204`.

### E-AUTH-04 `GET /auth/me` - Current user · MVP

| Permission | Idempotency | Success | Requirements |
|---|---|---|---|
| authenticated (any permission) | n/a | 200 `MeResponse` | FR-AUTH-11 |

**Response `MeResponse`**: `id` (UUID), `username`, `displayName`, `roles` (array), `permissions` (array), `lastLoginAt` (timestamp or null).
No hash, no token.
**Errors**: common set only (401 without a token).
**Example**: `-> 200 {"id":"7c1e...","username":"owner","displayName":"Owner","roles":["OWNER"],"permissions":["CHIT_MANAGE","DOCUMENT_MANAGE"],"lastLoginAt":"2026-10-07T03:40:00Z"}`

### E-AUTH-05 `POST /auth/password` - Change own password · POST-MVP

| Permission | Idempotency | Success | Requirements |
|---|---|---|---|
| authenticated | none | 204 | FR-AUTH-15 |

**Request**: `currentPassword` (`@NotBlank @Size(max = 200)`), `newPassword` (`@NotBlank @Size(min = 10, max = 200)`). All refresh tokens of the
user are revoked afterwards.
**Errors**: 401 `INVALID_CREDENTIALS` (wrong current password).
**Example**: `{"currentPassword":"Correct-Horse-9","newPassword":"Another-Horse-10"}` -> `204`.

### E-AUTH-06 `POST /users` - Create a user · POST-MVP

| Permission | Idempotency | Success | Requirements |
|---|---|---|---|
| `USER_MANAGE` | none | 201 + `Location: /api/v1/users/{id}`, `UserResponse` | FR-AUTH-14 |

**Request**: `username` (`@NotBlank @Pattern(regexp = "^[a-zA-Z0-9._-]{3,100}$")`), `displayName` (`Name200`),
`password` (`@NotBlank @Size(min = 10, max = 200)`), `roles` (`@NotEmpty`, values `OWNER`, `STAFF`).
**Response `UserResponse`**: `id`, `username`, `displayName`, `active`, `roles`, `lastLoginAt`, audit fields.
**Errors**: 409 `DUPLICATE_RESOURCE` (username exists).
**Example**: `{"username":"ravi","displayName":"Ravi","password":"Staff-Pass-01","roles":["STAFF"]}` -> `201`.

### E-AUTH-07 `GET /users` - List users · POST-MVP

`USER_MANAGE`; `PageResponse<UserResponse>`; filter `active` (boolean); sort `username`, `createdAt`. FR-AUTH-14. Errors: common set.
Example: `GET /api/v1/users?active=true` -> `200 {"content":[{"username":"owner","active":true,"roles":["OWNER"]}],"page":0,"size":20,"totalElements":1,"totalPages":1}`.

### E-AUTH-08 `POST /users/{id}/deactivate` - Deactivate a user · POST-MVP

`USER_MANAGE`; 200 `UserResponse`; revokes all refresh tokens of the user; audit `USER_DEACTIVATED`. Errors: 404 `RESOURCE_NOT_FOUND`;
409 `INVALID_STATE_TRANSITION` (already inactive, or the last active OWNER). FR-AUTH-14.
Example: `POST /api/v1/users/9a1.../deactivate` -> `200 {"id":"9a1...","active":false}`.

### E-AUTH-09 `POST /users/{id}/password-reset` - Reset a user's password · POST-MVP

## 9. Payments and settlement (`/payments`) - module finance

One endpoint records every settlement; `purpose` selects the counterparty role, the allocation table and the ledger direction
(customers `RECEIVED` -> ledger `IN`; suppliers, manufacturers and workers `PAID` -> ledger `OUT`). Payment, allocations and the
financial transaction commit together (FR-PAY-06). The party row is locked while allocating so two payments of one party can never
allocate the same outstanding twice (FR-PAY-24).

## 11. Loans (`/loans`) - module loans

A loan received is a liability (not revenue); principal repayment reduces it (not an expense); interest is an expense (FR-LOAN-08).
Loan payments are financial transactions linked by `loan_id` (no separate table).

**`LoanResponse`**: `id`, `loanNumber` (`LON-...`), `lender` (`PartyRef`, role `LENDER`), `loanType`, `principalAmount`,
`repaidBeforeGoLive` (money; 0.00 for loans received in the system), `principalRepaid` (Σ principal repayments, net of reversals),
`outstandingPrincipal` (`principalAmount - repaidBeforeGoLive - principalRepaid`), `interestPaid` (net of reversals), `startDate`,
`dueDate`, `interestRatePercent` (informational), `interestNotes`, `status`, `existingAtGoLive` (boolean), `receivedTransactionId` (null for
existing loans), `payments[]`: `{ transactionId, transactionType (LOAN_PRINCIPAL_REPAYMENT / LOAN_INTEREST_PAYMENT), amount, date, account,
paymentMethod, periodNote, reversed, reversalTransactionId }`, `notes`, audit fields.

**Request block `LoanTerms`**: `lenderId` (`Id`; active party with `LENDER`), `loanType` (`LoanType`, required), `principalAmount` (`Money+`),
`startDate` (`BizDate`), `dueDate` (date, optional, `>= startDate`), `interestRatePercent` (optional, `@DecimalMin("0.000") @Digits(integer = 3, fraction = 3)`),
`interestNotes` (`@Size(max = 500)`), `notes` (`Notes`).

## 12. Chits (`/chits`) - module chits

## 17. Notifications (`/notifications`) - module notifications

Notifications are created by a daily job at 08:00 Asia/Kolkata (FR-NTF-02) and sent after commit through `NotificationProvider` with up to
3 retries (FR-NTF-04); none of that is an endpoint. Kinds per purchase: `DUE_SOON` on `dueDate - daysBeforeDue`, `DUE_TODAY` on the due date,
`OVERDUE` every `overdueRepeatDays` after it until paid; one notification per purchase, kind and date (deduplicated). Fully paid purchases resolve
their open notifications (FR-NTF-03).

**`NotificationResponse`**: `id`, `notificationType`, `kind` (`ReminderKind`), `priority`, `party` (`PartyRef` or null), `referenceType`,
`referenceId`, `referenceNumber`, `message`, `scheduledAt`, `sentAt`, `status`, `attempts`, audit fields.

FR-NTF-05. Example: `GET /api/v1/notifications?status=PENDING` -> `200 {"content":[{"notificationType":"SUPPLIER_DUE","kind":"OVERDUE","referenceNumber":"PUR-2026-0003","status":"PENDING"}],...}`

### E-NTF-02 `GET /notifications/configurations` - Read configurations · MVP

`FINANCE_VIEW`; 200 array of `{ notificationType, enabled, daysBeforeDue, overdueRepeatDays, priority }`. FR-NTF-01.

### E-NTF-03 `PUT /notifications/configurations/{type}` - Update a configuration · MVP

| Permission | Idempotency | Success | Requirements |
|---|---|---|---|
| `FINANCE_MANAGE` | none (PUT is idempotent) | 200 configuration | FR-NTF-01 |

## 18. Documents (`/documents`) - module documents

Files are supporting records only: uploading never changes the referenced record (FR-DOC-05). Files are stored under a generated id through
`FileStorage` (local disk in the MVP), never under the client's file name (FR-DOC-02). Documents are never overwritten or deleted (FR-DOC-04).

**`DocumentResponse`**: `id`, `documentType`, `fileName` (sanitised original name), `contentType`, `sizeBytes`, `referenceType`
(`DocumentReferenceType` or null), `referenceId`, `supersedesDocumentId` (or null), `status`, audit fields. `storagePath` is never returned.

### E-DOC-01 `POST /documents` - Upload a document · MVP

| Permission | Idempotency | Success | Requirements |
|---|---|---|---|
| `DOCUMENT_MANAGE` | none | 201 + `Location: /api/v1/documents/{id}`, `DocumentResponse` | FR-DOC-01, FR-DOC-02, FR-DOC-04, FR-DOC-05, NFR-REL-05 |

**Request** (`multipart/form-data`)

| Part | Type | Required | Validation | Notes |
|---|---|---|---|---|
| `file` | file | yes | size 1 byte to 10 MB (larger is 400 `VALIDATION_FAILED`); content checked from the bytes: PDF, JPEG or PNG (else 415 `UNSUPPORTED_MEDIA_TYPE`) | |
| `documentType` | `DocumentType` | yes | | |
| `referenceType` | `DocumentReferenceType` | no | together with `referenceId` | absent = no reference |
| `referenceId` | UUID | with `referenceType` | the referenced record must exist (else 404) | |
| `supersedesDocumentId` | UUID | no | existing document (else 404) | a corrected file; both stay listed |

Any other form field (for example `amount`) is ignored.
**Errors**: 400 `VALIDATION_FAILED` (over 10 MB, `referenceId` without type); 404; 415 `UNSUPPORTED_MEDIA_TYPE`; 500 `INTERNAL_ERROR` when storage is
unavailable (no database row remains).
**Example**: `multipart: file=bill.pdf (2 MB), documentType=PURCHASE_BILL, referenceType=PURCHASE, referenceId=8a1b...` -> `201 {"id":"d0c1...","fileName":"bill.pdf","contentType":"application/pdf","sizeBytes":2097152,"referenceType":"PURCHASE"}`

### E-DOC-02 `GET /documents` - List documents · MVP

`DOCUMENT_MANAGE`; `PageResponse<DocumentResponse>`; query `referenceType`, `referenceId`, `documentType`, `from`, `to` (upload date), sort `createdAt`
(default desc). FR-DOC-03. Example: `GET /api/v1/documents?referenceType=PURCHASE&referenceId=8a1b...` -> `200 {"content":[...],...}`

### E-DOC-03 `GET /documents/{id}` - Document metadata · MVP

`DOCUMENT_MANAGE`; 200 `DocumentResponse`; 404. FR-DOC-03. Example: `-> 200 {"documentType":"PURCHASE_BILL","fileName":"bill.pdf",...}`

### E-DOC-04 `GET /documents/{id}/content` - Download · MVP

`DOCUMENT_MANAGE`; 200 with the stored content type, `Content-Disposition: attachment; filename="<sanitised name>"`, `Content-Length`; 404 when

`DOCUMENT_MANAGE`; request `partyId`, `message` (`@Size(max = 500)`); 202; sent after commit, failure never affects business data. FR-DOC-06,
FR-NTF-08. Example: `{"partyId":"5d0c...","message":"Your bill"}` -> `202`.

### E-DOC-06 `POST /documents/ocr-extractions` - Extract data from a supplier bill · POST-MVP

## 22. Decisions made while writing

| # | Topic | Decision | Reason / impact on other documents |
|---|---|---|---|
| 1 | Money and weight on the wire | JSON **numbers** with exact scale (2 / 3 decimals), serialized from `BigDecimal`; more decimals in a request are rejected, never rounded | Matches `03-ARCHITECTURE.md` 7.4; the client parses them as `BigDecimal` |
| 2 | Payment model | One `POST /payments` with `purpose` (`CUSTOMER`/`SUPPLIER`/`MANUFACTURER`/`WORKER`); `direction` (`RECEIVED`/`PAID`) is derived | `04-DATA-MODEL.md` 7.2 shape; replaces the `direction IN/OUT` wording of `02` (ledger direction stays `IN`/`OUT`) |
